# Real model-turn protocol

This is an execution procedure, not evidence that a model run has occurred.

The coordinator must obtain a verified fresh deployment and role-wallet bootstrap before starting day one. Sponsor deposits and backer commitments are decisions for actual character turns; role-wallet funding alone is neither reserve funding nor a guarantee. The disabled workflow must remain disabled until exact source, action adapter, receipt checks, budgets and recovery are reviewed and rehearsed.

For each of seven virtual days, run the market's ordered queue. Obtain `brief` for the next actor. Start one new native Codex collaboration agent with `fork_turns="none"`, supplying only that exact brief and requiring one JSON response. Do not give the actor the repository, full persona roster, a signing tool, another character's messages, or an earlier conversation. Do not instruct it to achieve a desired result. Do not reuse an agent context for another character or day.

The actor returns its own decisions, original work, messages and journal. Preserve its exact final response; parse and submit it without editing. Record the actual execution provider, fresh-context setting, actor and day, hashes of the complete input and output, and an internal invocation receipt. Keep private runtime identifiers outside the public archive. A provenance label or a unit-test fixture cannot establish that the invocation occurred.

Process commands through the market. Preserve refusals and mistakes. If a response is malformed, retain it as a failed turn and use a separately recorded correction turn with the same character's visible state; do not silently replace it. Count correction calls separately from the required 700 character-day turns.

Resolve proposals only through the independently reviewed signing boundary and exact transcript-bound permissions. Record an intended transaction before broadcasting, reconcile its hash/nonce on uncertainty, and import only independently verified semantic outcomes. Never count a transfer proposal as a wage or a guarantee proposal as coverage. Archive each day's complete turn set, transaction journal and pinned chain-state readbacks before advancing. A day must not advance while an intention remains unresolved.

Close new guarantee admissions after day four. Days five through seven are available for delivery, review, payment, contribution and dispute resolution. Public chain timestamps remain real; a virtual day is not an elapsed onchain day. Claims require the recorded adjudicator's evidence and valid real settlement window, never a clock shortcut or a desired terminal result.

At day seven, pause new admissions, independently reconcile all open guarantees and unpaid contributions, and record retained reserve, dues, stake and role-wallet balances. A paused contract with unresolved obligations is an incomplete teardown. Preserve failures rather than force claims to make the run look complete.

After all seven days and teardown are verified, choose a character from the complete records. Select a concrete dilemma and consequence that a person can follow. Quote only the actual messages of two separately invoked characters. Describe the experience as simulated and the token as test USDC. Publish the human story with its verification rows, then the GitHub agent-board and Moltbook companions through the existing process.
